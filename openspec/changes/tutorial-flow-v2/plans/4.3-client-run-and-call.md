# 4.3 Client run and the call act

Ticket: HOO-2357 "Tutorial client run and call act: hello comes back from
devnet". Stacked on #241 (HOO-2356, task 4.2), whose `actRunner`,
`fundForDeploy`, `devnetExplorerUrl` and `tutorial_action_run` this task
uses. The finish card's receipt is #248's (HOO-2352, task 3.4); this task
fills its `receipt` shape.

## Success metric

Every finished tutorial shows a receipt that opens in Explorer. Check: the
e2e asserts the Explorer link of the last call, before 10 Nov.

## Design gaps (decided here, sent to the designers' batch)

No source draws the run or call result card; the DS prototype has none, the
designers' spec names only "Transaction confirmed, Copy, Explorer" and, for
a failure, "Program logs and a plain reason · Explain, Try again".

1. **Landed card meta line.** Head: "Confirmed" and "Sent from client.ts" /
   "Sent from the chat". Meta line under the large log line: the signature as
   a short key with ↗ (the Explorer link), "{n} CU", "fee {fee} from your
   wallet", "{seconds}". No separate Explorer or Copy button (D9).
2. **Failed card.** Head: "Run failed" / "Call failed" (or "<instruction>
   refused" with the Anchor error) and the plain reason; body: the last
   program log lines in mono. No Explain or Try again: the act card stays
   live and runs again, and Explain belongs to the assistant (task 3.6).
3. **A run that sent nothing.** Failed card "Run failed · client.ts sent no
   transaction. See the terminal".
4. **Funding floor.** A run or call tops the wallet up when it holds under
   0.5 SOL (Zero Copy's rent), as a "Funding your wallet" first stage, like
   the deploy.

## Steps

1. `RunInput.log`: the step goal's `log` pattern, set by the reducer's `act`
   case, so the runner picks the card's line without the definition.
2. `progress.ts`: `Receipt` (#248's shape plus `computeUnits`) and
   `receipt?` on a landed run or call; `reason?: "no_wallet" | "no_funds"` on
   a failed one; `outcomeOf` reads it.
3. `runners/transactions.ts` (pure): pick the line, parse an Anchor error
   into a `Refusal`, build the receipt, fold several transactions into one
   result. In-source tests on real devnet logs.
4. `runners/capture.ts`: `captureSends(connection, fn)` wraps the
   connection's `sendEncodedTransaction` for the run, recording each
   signature and each refused send with its simulation logs, and restores
   it. In-source tests with a fake connection.
5. `runners/run-call.ts`: the run and call orchestration over a port
   (wallet, funding, send, fetch, decode), stages, failures as results.
   In-source tests with a stubbed port.
6. `runners/real-run.ts`: the port over `PgJsRuntime`,
   `PgProgramInteraction`, `PgConnection` and Anchor's
   `BorshInstructionCoder`; plugged into `tutorialRunner`.
7. `BaseResultCard`: the meta line and the failed body; component tests in
   `turns.test.tsx`.
8. Hello Anchor's step 3 and 4 on devnet by hand (Playwright), screenshots.

## Verify

`yarn run check`; the in-source and component tests above; the by-hand run.
