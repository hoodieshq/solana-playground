# Win and Finish Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans
> (inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`)
> syntax for tracking.

**Goal:** Every step ends on a win card, and the tutorial ends on a finish
card with the proof first: the transaction, what was learned, and the next
tutorial. This replaces the feed's `WinStandIn` and `FinishStandIn`
(task 3.3, `TODO(tutorial-flow-v2 3.4)`).

**Architecture:** Render only, in `widgets/tutorial-conversation` (design
D3), beside the feed's other cards. The engine (task 3.1) already marks the
step passed at the win, times the finish 400 ms later and sends
`tutorial_finished`; this ticket draws the two cards and wires their
buttons. Each card is a `Base<Name>` that takes everything through props;
the connected `TutorialConversation` hands them the handlers. The finish
turn of `ConversationView` gains the facts the card reads (the time from
Start and the last call's result), so the card computes nothing.

**Tech Stack:** React 19, Tailwind 4, `shared/ui` (`button`, `kbd`, `tag`,
`collapsible`, `copy-button`, `tooltip`), lucide icons, vitest in-source
blocks and Testing Library.

**Spec:** `openspec/changes/tutorial-flow-v2/specs/tutorial-conversation/spec.md`,
"Each step ends on a win card" (scenario "Finishing Hello Anchor"), and the
receipt rows of `tutorial-runs` ("every address row SHALL carry Copy and an
Explorer link", the wallet copy table's "Receipt signer row", "Finish card
meta" and "Finish receipt"). Linear HOO-2352.

## Sources, and where they differ

- **Ticket vs spec on the receipt:** the ticket says Copy + Explorer on every
  address row and Copy receipt as an icon on the "Transaction details" row;
  the spec says the same (Almaz, 3.15 and 3.25, 28 Oct). They agree.
- **What a call's result holds today:** `signatures`, the picked log `line`
  and `called`. The receipt needs the fee, the signer, the accounts and the
  log, which only the call runner (task 4.3, HOO-2357) can fill. Decided
  (Natalia, 2 Nov): add them as **optional** fields of the `run`/`call` ok
  result now, as the type's comment allows ("the run tickets add to them,
  never rename"). The card draws each row only when its field is there.
  Until 4.3, a receipt shows the signature (Copy + Explorer) and the log
  line, and Copy receipt copies what it shows.
- **"Open Call"** opens the Call panel, task 4.4 (HOO-2358), not built yet.
  Decided (Natalia, 2 Nov): the win card takes an optional `onOpenCall`; the
  connected feed passes none until 4.4 provides an opener, so the button
  does not show yet. `TODO(tutorial-flow-v2 4.4)` marks the spot. "Write it
  in client.ts" (a step passed from the Call panel) opens `client/client.ts`
  through the feed's `showLine` and works now; it shows only when the
  step's `via` is `call_panel`, which also only 4.4 can produce.
- **Enter goes Next** while the win is live (spec). Decided (Natalia,
  2 Nov): the intro card's rule, Enter on the document while nothing else
  holds focus, with the feed's `typing` guard.
- **"All tutorials"** opens the catalog's Tutorials page, which lives in
  another widget. A widget may not import a widget, so
  `TutorialConversation` takes `onAllTutorials` as a prop and
  `views/flow/Flow.tsx` (a legacy root, free to import both) passes
  `catalogPage.open("tutorials", "nav")`, as the frame's back link already
  does. No new `CatalogVia`: `tutorial_next_opened` is the finish card's own
  measure.
- **"Next: <tutorial>"** reads the next tutorial's name, found by
  `finish.next` (a slug) among the listed tutorials, and opens it with
  `PgTutorial.open`. A `next` that names no listed tutorial is already
  rejected by the loader (task 1.1), so the card always has one when `next`
  is set; with `next: null` the card shows only "All tutorials".
- **The last step's win has no Next** (spec); the view already marks it
  `last`. The finish follows it on its own after 400 ms (engine).

## Global Constraints

- Every Explorer link opens `https://explorer.solana.com/<tx|address>/<id>?cluster=devnet`
  in a new tab (`tutorial-runs`, "Every Explorer link SHALL open Solana
  Explorer on the devnet cluster in a new tab").
- No stat pills on either card, and none in the data (spec; Almaz 3.14).
- No "See summary" (Almaz 3.15).
- The wallet copy is verbatim from `tutorial-runs`: "Your wallet · signer",
  "<n> steps · <time> · devnet only, nothing real spent", "Fee <fee> devnet
  SOL".
- Ids, `aria-label`s and test ids of the stand-ins carry over: the win's
  `aria-label` stays "Step n done", the finish's "Finished".
- The client-v2 rules hold: Base + connected pairs, `Button`/`CopyButton`
  from `shared/ui` with `reportButtonFailure` on `CopyButton`, in-source
  tests for pure modules, no spreads in fixtures, no nested ternaries.

## Telemetry

Confirmed by Natalia on 2 Nov. On `entities/tutorial`'s tracker, like the
feed's:

- `tutorial_next_opened` when "Next: <tutorial>" on the finish opens the next
  tutorial, with `tutorial` and `next` (both slugs). The ticket's success
  metric reads `tutorial_started` after `tutorial_finished`; this says the
  finish card was the way there.
- `tutorial_receipt_copied` when Copy receipt is pressed, with `tutorial`.
  The shared `CopyButton` reports no success and `shared/ui` is not edited by
  hand, so the press is counted; a copy the clipboard refuses still goes to
  `reportButtonFailure`.

Not added: Next on a win (the engine's step move is already visible in
`tutorial_step_passed` and the next step's events), "All tutorials"
(`catalog_shown` says the page opened), Explorer links (a plain link out).
