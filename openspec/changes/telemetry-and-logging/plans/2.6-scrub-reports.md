# Scrub what reaches Sentry: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Sentry report from the browser carries neither the user's program output nor a secret key (HOO-1800).

**Architecture:** pure rules in `shared/lib/reporter/scrub.ts`; `reporter/sentry.ts` builds its `Sentry.init` options in an exported `sentryOptions(config)` that wires them as `beforeBreadcrumb` and `beforeSend`, so the integration test runs the real SDK with exactly the production options plus a recording transport.

**Tech Stack:** `@sentry/react` 11.4, vitest.

**Spec:** `openspec/changes/telemetry-and-logging/specs/client-v2-logging/spec.md`, requirement "Reports carry no user code or secret key"; design decision 12.

## Success metric (from the ticket)

A report built through the real Sentry SDK, from a session where the user's test printed a 64-byte secret key to the console and an error message carries a secret key, reaches the transport with neither: the test output is not among its breadcrumbs and the key reads as redacted (integration test in `reporter/`).

## Global Constraints

- Redaction marker: `[redacted]`.
- Secret-shaped: base58 run of 64+ characters (`[1-9A-HJ-NP-Za-km-z]{64,}`), hex run of 64+ (`[0-9a-fA-F]{64,}`), a list of 32+ integers 0–255 (in a string: `[` n `,` n … `]`; as a value: an array or typed array of 32+ such numbers).
- Kept: base58 of 32–44 characters (public keys), feedback text (Sentry runs `beforeSend` on error events only; feedback is untouched by construction).
- Console breadcrumb kept only when `typeof args[0] === "string"` and it matches `^\[[a-z0-9-]+:[a-z0-9-]+\]$` (the console provider's tag, `providers/console.ts` `argsOf`); `data.arguments` always deleted.
- `@sentry/react` is imported only from `reporter/sentry.ts` (`slice-structure.test.ts`), so `scrub.ts` types its inputs structurally and imports nothing from Sentry.

## Review Focus

1. A base58 transaction signature (87–88 chars) is redacted too: accepted, signatures are public but a 64-byte key looks the same; test pins it.
2. A key embedded inside a longer sentence (`"bad key 4x…z in wallet"`) is redacted without eating the sentence: test.
3. Nested extras (`{ wallet: { secretKey: Uint8Array(64) } }`) are redacted at depth: test.
4. A `Uint8Array(32)` public key's bytes as an array would be redacted: accepted (a byte array is not how we log public keys); not tested further.
5. A logger breadcrumb whose message quotes a key keeps the breadcrumb, key redacted: test.

### Task 1: The scrub rules

**Files:**
- Create: `client-v2/src/shared/lib/reporter/scrub.ts` (in-source vitest block, the logger's convention)

**Interfaces:**
- Produces:
  - `redact(value: unknown): unknown` — strings get patterns replaced; arrays/typed arrays of 32+ bytes become `"[redacted]"`; plain objects and arrays recurse (depth cap 8, cycles via a `WeakSet`); anything else unchanged.
  - `scrubBreadcrumb<B extends { category?: string; message?: string; data?: Record<string, unknown> }>(crumb: B): B | null` — console rule above, then `message` and `data` through `redact`.
  - `scrubEvent<E extends ScrubbableEvent>(event: E): E` — redacts `message`, `exception.values[].value`, `breadcrumbs[]` (via `scrubBreadcrumb`, dropping nulls), `extra`, `contexts`, `tags`, `request.url`.

- [ ] **Step 1: Write the failing tests** (`describe("shared/lib/reporter/scrub")`):
  - `redact` replaces an 88-char base58 key inside `"bad key <key> in wallet"` with `"bad key [redacted] in wallet"`.
  - `redact` keeps a 44-char public key.
  - `redact` replaces a 64-char hex run.
  - `redact` replaces `"[1,2,…64 numbers]"` text, and returns `"[redacted]"` for `new Uint8Array(64)` and a 64-number array; keeps `[1, 2, 3]`.
  - `redact` recurses: `{ wallet: { secretKey: new Uint8Array(64) } }` → `{ wallet: { secretKey: "[redacted]" } }`; survives a cycle.
  - `scrubBreadcrumb` returns `null` for `{ category: "console", data: { arguments: ["  ✔ passes"] } }`; keeps `{ category: "console", message: "[persistence:sync] <key>", data: { arguments: ["[persistence:sync]", "x"] } }` as message `"[persistence:sync] [redacted]"` with no `data.arguments`; leaves a `fetch` crumb's URL alone unless it holds a key.
  - `scrubEvent` redacts exception value, `extra`, `contexts`, `tags`, and drops a user-output breadcrumb.
