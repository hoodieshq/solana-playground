ITERATION 3 — CONCEPT
Motion language
Motion is status, not decoration: something moves only when the system's state changes, and the movement says what changed. Everything below is CSS transitions + keyframes — no animation library, fully expressible in React 17 + styled-components.
DURATION & EASING TOKENS
instant · 80ms hover surfaces, focus rings, pressed states linear
fast · 140ms tab switches, chip toggles, tooltip in cubic-bezier(0.2, 0, 0, 1)
base · 220ms stage crossfade, cards entering, modal in cubic-bezier(0.2, 0, 0, 1)
slow · 320ms console drawer, panel collapse, layout shifts cubic-bezier(0.32, 0.72, 0, 1)
THE FIVE MOVEMENTS (LIVE)
1 · Working = gradient sweep
While a build or deploy runs, its stepper pill and progress bar sweep the brand gradient. The only looping animation in the product.
2 · Results rise in
Error cards, diff proposals, tx results: fade + 8px rise at base. Never sideways, never bouncy.

3 · Console is a drawer
Height animates at slow with the decel curve; content fades in 60ms behind it.

4 · Stage change = crossfade
Switching Write → Build swaps the center surface with a 220ms crossfade; panels never fly across the screen. The active stepper dot pulses once on arrival.

5 · Reduced motion = same information
Under prefers-reduced-motion every transition collapses to an opacity change and the sweep becomes a static gradient at 60% opacity. State changes stay visible — nothing communicates through movement alone (the pulsing dot also changes color; the drawer also changes its chevron).
Implementation notes: tokens live in the theme (theme.default.transition already exists upstream — extend, don't replace) · only transform and opacity animate, height only on the drawer · no transition: all.
