# Модель, агент и путь к продакшену — ресерч перед презентацией

> Internal research snapshot, 2026-08-20. Describes two providers; the
> shipped client-v2 has four (Demo, Anthropic, OpenAI-compatible,
> Gemini/OpenRouter presets).

Дата: 2026-08-20. Для внутреннего чтения (Слава), потом — основа слайдов.
Цены и возможности API — по справочнику Anthropic на 2026-06, не по памяти.

---

## 0. TL;DR — пять тезисов, которые надо донести

1. **В демо нет «дешёвой бесплатной модели».** У нас два провайдера:
   `scripted` — заскриптованный проход одного сценария *без модели вообще*,
   и `anthropic` — настоящий `claude-opus-5` через Tool Runner по ключу
   пользователя. Так и надо говорить: «сценарий заскриптован, но каждый шаг —
   чтение ошибки, диф, одобрение, запись файла, сборка, деплой — настоящий».
2. **Обучать модель не нужно.** Задача решается не fine-tuning'ом, а
   контекстом: реальный stderr компилятора, реальные файлы, IDL, документация
   Solana через MCP, набор правил про ограничения среды. Fine-tuning здесь
   дороже, медленнее и устаревает вместе с версией Anchor.
3. **Меняется не модель, а место, где крутится агент.** Сегодня — браузер и
   ключ пользователя. Продакшен — маленький открытый прокси-сервис: квота для
   анонимов, ключ не в браузере, подключение MCP, журнал действий. Это уже
   записано как D1-B в `decisions.md`; демо его не требовало.
4. **Модель — не главный выбор; главный — провайдер-агностичный слой.**
   Сравнение вендоров, цен, бенчмарков и практики аналогов — в отдельном
   документе `2026-08-20-model-landscape.md`; там же честные варианты A–F
   для Фонда. В демо подключён Anthropic (Opus 5), потому что это единственный
   путь, где заземление в `mcp.solana.com` работает без нашего бэкенда.
5. **«Системные файлы» — это промпт, описания инструментов, skills и набор
   эталонных кейсов для проверки.** Именно их мы будем писать и развивать —
   это и есть замена «обучению».

## 1. Что реально есть в коде сейчас

Слой модели — `client/src/views/sidebar/assistant/model/`:

| Файл | Что делает |
| --- | --- |
| `types.ts` | Интерфейсы `Provider` и `ToolDefinition` без привязки к вендору. Объявлены три провайдера: `scripted`, `anthropic`, `openai` (последний — заглушка «не подключён»). |
| `tools.ts` | Шесть инструментов: `list_files`, `read_file`, `get_build_error`, `write_file`, `build`, `deploy`. Ворота одобрения — *внутри* `run` каждого изменяющего инструмента: он не возвращает результат, пока пользователь не нажал Apply. |
| `prompt.ts` | Системный промпт: правила поведения (~480 слов) + `assistant-context.md` (~1100 слов). Отдельно — снимок проекта на каждый ход (файлы, кластер, открытый файл, последний stderr). |
| `anthropic.ts` | `@anthropic-ai/sdk`, `client.beta.messages.toolRunner`, модель `claude-opus-5`, adaptive thinking, `effort: high`, стриминг, `cache_control` на стабильной части промпта, `max_iterations: 12`. |
| `scripted.ts` | Демо без сети и ключа. Распознаёт два типа вопросов (roadmap / build error) и умеет чинить ровно один баг — строковый литерал, присвоенный целому типу (E0308 из фикстуры). **Вызывает те же инструменты**, что и живая модель. |

Важно для честности на презентации:

- **Реально в обоих режимах:** чтение вывода компилятора, чтение файла,
  карточка дифа, кнопка одобрения, запись файла, сборка на продакшен-сервере
  `api.solpg.io`, деплой в devnet.
- **Заскриптовано в `scripted`:** «рассуждение» — текст объяснения и выбор
  правки. Модель там не вызывается.
- **Живой режим** (`anthropic`) работает при наличии ключа; ограничения —
  ключ держится в памяти вкладки (D3), нет квоты, нет журнала на сервере.

Рекомендуемая формулировка для заказчика: *«Для демо мы вынесли рассуждение
в сценарий, чтобы показ не зависел от сети и ключа. Всё, что агент делает с
проектом, — настоящее. Живой режим на Claude Opus 5 подключён той же кнопкой и
работает с ключом»*. Это сильнее, чем «использовали дешёвую модель», и — правда.

Более того, это было предусмотрено самим заданием:
`docs/internal/brief/task-01-assistant-panel.md`, шаг 3 — *«If wiring a real
model costs more than an hour, ship the panel with a scripted response for the
demo scenario first, then swap in the real call. Mark clearly in the code which
one is active»*. Мы сделали ровно это, и активный провайдер виден в футере панели.

## 2. Нужно ли обучать модель? Нет. Вот почему

Вопрос, который заказчик задаст почти наверняка: «вы будете обучать модель
на Solana?». Ответ — нет, и это осознанное решение, а не экономия.

**Почему fine-tuning не подходит для этой задачи**

- Знание, которое нужно ассистенту, **меняется быстрее, чем цикл обучения**:
  Playground прибит к `anchor-lang 0.29` и `solana-program 1.16`, upstream
  собирается это менять. Дообученная модель «застынет» на одной версии.
- Ошибка в 90 % случаев диагностируется **из самого текста компилятора и
  кода** — это общая компетенция Rust/Anchor, которой у фронтирных моделей
  и так достаточно. Проблема не в том, что модель «не знает Solana», а в том,
  что ей **не дали контекст** (stderr, файл, версия фреймворка, список крейтов).
- Fine-tuning требует датасета «сломанный код → правильная правка» в тысячах
  примеров, бюджета на прогоны и инфраструктуры для оценки. На выходе —
  закрытый артефакт, который противоречит принципу «всё открыто».
- У Anthropic фронтирные модели не дообучаются пользователями; у открытых
  моделей это возможно, но означает собственный хостинг инференса — отдельный
  продукт, а не фича Playground.

**Что делает то же самое дешевле и лучше — четыре слоя контекста**

| Слой | Что это | Статус |
| --- | --- | --- |
| 1. Состояние проекта | Файлы, открытая вкладка, IDL, program id, кластер, **сырой stderr** последней сборки (для этого и нужен D4). | Сделано |
| 2. Правила среды | Системный промпт: «крейты — фиксированный список», «тесты — TypeScript на devnet», «Anchor 0.29, не предлагай API новее», «сначала прочитай файл», «минимальная правка». | Сделано, будет расти |
| 3. Знания экосистемы по запросу | MCP-серверы Solana (документация), официальный Solana skill — подключаются как инструменты, модель зовёт их, когда нужно. | Сделано: skills на всех провайдерах, MCP только на Anthropic; Explorer MCP недостижим, см. §5 |
| 4. Эталонные кейсы (evals) | Набор сломанных программ с ожидаемой правкой. Прогоняем при каждом изменении промпта или смене модели — это наша «метрика качества». | Не начато, см. §7 |

Слои 2–4 — это и есть «системные файлы», о которых шла речь. Их пишут
люди, они лежат в репозитории, они открыты и ревьюятся как код.

## 3. Модель: цены и стоимость хода (см. также `model-landscape.md`)

Актуальные цены Anthropic API (за 1M токенов, первый вендор):

| Модель | Вход | Выход | Контекст | Для чего нам |
| --- | --- | --- | --- | --- |
| Claude Opus 5 | $5 | $25 | 1M | Основной агент: объяснение ошибки, патч, многошаговые задачи |
| Claude Sonnet 5 | $2 (цена запуска сделана постоянной 2026-08-10) | $10 | 1M | Режим бесплатной квоты для анонимов; простые вопросы |
| Claude Haiku 4.5 | $1 | $5 | 200K | Вспомогательное: заголовки, чипы контекста, классификация запроса |
| Claude Fable 5 | $10 | $50 | 1M | Не берём: дороже вдвое, ход длится минуты, выигрыш на «почини E0308» не окупается |

**Почему Opus 5 — основной.** Цена ошибки агента в этом продукте — не
«плохой ответ в чате», а **неправильный патч, применённый новичком**, за
которым следует ещё одна неудачная сборка и потеря доверия. Здесь качество
важнее цены, а цена всё равно измеряется центами. Opus 5 даёт adaptive
thinking по умолчанию, `effort` как рычаг стоимости, 128K вывода и работает с
MCP-коннектором и task budgets.

**Почему Sonnet 5 — для квоты.** Анонимный пользователь без ключа получает
N ходов за наш счёт. Sonnet 5 втрое дешевле на выходе и достаточно силён для
типовых ошибок новичка. Переключение — это одна строка в конфиге провайдера.

**Почему не OpenAI / Gemini / открытые модели.** Не потому, что они хуже, а
потому что у нас есть вещи, которые делают именно Tool Runner и Messages API
удобными для *этого* продукта: хуки до выполнения инструмента (ворота
одобрения внутри цикла), MCP-коннектор на стороне API, кэширование префикса,
compaction. Слой `Provider` уже абстрактен — если Фонд назовёт другого
вендора, пишется второй адаптер, UI и инструменты не меняются. Это один из
открытых вопросов к Фонду в `product-brief.md`.

### Сколько это стоит — оценка одного хода

Допущения: системный промпт ~2.5K токенов (кэшируется), снимок проекта с
открытым файлом ~1.5K, описания инструментов ~0.6K, в ходе «объясни и почини»
модель делает 3–4 вызова инструментов, каждый — новый запрос с растущей
историей; суммарный вход ~15–20K (из них ~10K из кэша, 10 % цены), выход с
thinking ~3–4K.

| Модель | Оценка за ход «ошибка → патч» | 100 ходов |
| --- | --- | --- |
| Opus 5 | ~$0.12–0.20 | $12–20 |
| Sonnet 5 | ~$0.05–0.08 | $5–8 |
| Haiku 4.5 | ~$0.02–0.03 | $2–3 |

Простой вопрос без инструментов («что такое PDA?») — в 5–10 раз дешевле.
Кэш важен: без `cache_control` вход дорожает примерно вдвое. Цифры — оценка
по структуре промпта, не замер; точные получим из `usage` в ответах API,
когда прогоним эталонные кейсы (§7).

Для квоты: 10 бесплатных ходов на Sonnet 5 ≈ $0.50–0.80 на пользователя.
1000 новых пользователей в месяц ≈ $500–800. Это порядок цифр для вопроса
«кто платит за инференс» — он тоже в списке вопросов к Фонду.

## 4. Как система будет работать дальше — три ступени

### Ступень 0 — сейчас: всё в браузере (D1)

```
Браузер ──(ключ пользователя)──▶ api.anthropic.com
   │
   ├─ Tool Runner: цикл модель ⇄ инструменты
   ├─ Инструменты → PgExplorer / PgCommand.build / deploy
   └─ Ворота одобрения — внутри run() инструмента
```

Плюсы: ноль инфраструктуры, ноль изменений в существующем клиенте, честно
работает. Минусы: ключ в памяти вкладки; нельзя дать квоту анонимам; нет
серверного журнала («traceability» из принципов); MCP-серверы пришлось бы
вызывать из браузера (CORS, ключи к MCP — тоже в браузере).

### Ступень 1 — продакшен: тонкий открытый прокси (D1-B)

```
Браузер ──▶ assistant-proxy (наш, открытый, отдельно от server/) ──▶ Anthropic API
   │             │                                                 │
   │             ├─ ключ Anthropic — только здесь                  ├─ MCP-коннектор →
   │             ├─ квота анонимов / BYOK-ключ пользователя         │   Solana Docs MCP,
   │             ├─ rate limit, журнал ходов (traceability)         │   Explorer MCP
   │             └─ конфиг модели (Opus/Sonnet), effort, промпт     │
   │                                                               │
   └─ инструменты по-прежнему исполняются в браузере ◀─────────────┘
      (файлы живут в IndexedDB пользователя; ворота одобрения там же)
```

Ключевые свойства:

- **Цикл агента остаётся тем же Tool Runner'ом**, только запущенным на
  прокси; вызовы `read_file`/`write_file`/`build` уезжают в браузер по
  WebSocket/SSE и возвращаются. Инструменты и ворота одобрения не переписываются.
- **Не трогаем `server/`** — это отдельный сервис, как требует
  ограничение «бэкенд не меняем». Стек — любой; логично Node/TypeScript, чтобы
  переиспользовать `tools.ts`/`prompt.ts` как есть.
- **MCP-коннектор** Messages API (`mcp_servers` + `mcp_toolset`, beta
  `mcp-client-2025-11-20`): Anthropic сам ходит к удалённому MCP-серверу —
  нам не нужен MCP-клиент ни в браузере, ни на прокси. Нужен только URL и,
  при необходимости, токен.
- **Квота**: анонимам — N ходов на Sonnet 5 по нашему ключу; со своим
  ключом — без лимита и с выбором модели. «Никогда не открытый безлимитный
  эндпоинт» — из принципов.
- **Журнал**: каждый ход — кто, какие инструменты, какие файлы изменены,
  сколько токенов. Это и «traceability», и данные для §7.

Стоимость: один маленький сервис + деплой. Это единственная новая
инфраструктура на всём пути.

### Ступень 2 — когда понадобится: долгие сессии и память

Уже доступно в API и включается на прокси без изменения клиента:

- **Compaction** (серверное сжатие истории) — для длинных разговоров.
- **Context editing** — чистка старых результатов инструментов.
- **Memory tool** — память между сессиями, если Фонд захочет
  персистентную идентичность пользователя (открытый вопрос в brief).
- **Subagents / дешёвая модель для подзадач** — например, Haiku
  суммирует длинный stderr, Opus делает патч.

**Что отвергли и почему** (кратко, полнее — `decisions.md` D1):

- *Claude Agent SDK* — это Claude Code как библиотека; его встроенные
  инструменты работают с реальной файловой системой, а наши файлы живут в
  IndexedDB браузера. Мы бы подняли сервис и отключили всё, ради чего он нужен.
- *Managed Agents* — Anthropic хостит и цикл, и песочницу с файлами; у нас
  файлы в браузере и сборка на `api.solpg.io`. Не наш случай, пока проекты
  не переедут на сервер.
- *Vercel AI SDK* — требует React 18+, клиент на React 17.

## 5. Заземление в экосистеме Solana

Проверено 2026-08-20 (репозитории, `tools/list` у живого эндпоинта):

| Источник | Статус | Что даёт нам |
| --- | --- | --- |
| **Solana Developer MCP** — `https://mcp.solana.com/mcp` · [solana-foundation/solana-mcp-official](https://github.com/solana-foundation/solana-mcp-official) | Активен (пуш 2026-08-19), публичный, **без авторизации**, Streamable HTTP | RAG по ~60 источникам (solana-docs, anchor-docs, kit, pinocchio, program-examples, сам solana-dev-skill, Helius/QuickNode). Инструменты: `Solana_Documentation_Search`, `get_documentation(section)`, `Solana_Expert__Ask_For_Help`, и — главное — **`program_autofixer(code, framework?)`**: линтер Anchor/Pinocchio-кода, возвращает issues + suggestions |
| **Официальный Solana skill** — [solana-foundation/solana-dev-skill](https://github.com/solana-foundation/solana-dev-skill), также `solana.com/SKILL.md` | Активен (пуш 2026-08-17), MIT, 552★ | `SKILL.md` + `references/`: `common-errors.md`, `compatibility-matrix.md`, `security.md`, `testing.md`, anchor/, kit/. Готовый формат для нашего «skill правил среды» (§6) |
| **Solana Explorer MCP** — в репо [solana-foundation/explorer](https://github.com/solana-foundation/explorer), `app/mcp/` | Код есть (с 2026-07-20), инструмент `inspect_entity`. Эндпоинт под бот-защитой Vercel (`x-vercel-mitigated: challenge`), но **проверено 2026-08-20: `x-vercel-protection-bypass` в query снимает её** — `200` без mitigation | Проверка задеплоенной программы/транзакции после деплоя. В реестре выключен; секрет вписывается в `queryParams` через Sources |
| `solana.com/llms.txt`, `llms-full.txt` | Есть | Документация в Markdown для статического контекста или своего индекса, если MCP недоступен |
| [awesome-solana-ai](https://github.com/solana-foundation/awesome-solana-ai) | Активен | Канал «подключить новый MCP/skill» из brief — реестр уже ведёт Фонд |
| solana-agent-kit (SendAI) и его MCP | On-chain actions, MCP-обёртка не обновлялась с 2025-05 | Не про документацию; не берём |

**Как подключаем.** `mcp.solana.com` **не отдаёт CORS-заголовки** — из
браузера напрямую его не вызвать. Но через **MCP-коннектор Messages API**
соединение с MCP-сервером устанавливает сама Anthropic: нам нужно передать
`mcp_servers: [{type: "url", url: "https://mcp.solana.com/mcp", name: "solana"}]`
и `tools: [{type: "mcp_toolset", mcp_server_name: "solana"}]` с beta-заголовком
`mcp-client-2025-11-20`. Это работает и из браузера (ступень 0), и с прокси
(ступень 1). Ограничения коннектора: только `https://` и публично доступные
серверы, только tools (не prompts/resources), OAuth-токен добываем сами, не
доступен на Bedrock/Vertex.

**Проверено 2026-08-20 (SDK 0.117.1), три вещи.** Первая: `mcp_servers`
совмещается с `toolRunner` — `BetaMCPToolset` входит в `BetaToolUnion`, а
`BetaToolRunnerParams` это `Omit<MessageCreateParams, 'tools'>` плюс массив
`BetaToolUnion | BetaRunnableTool`, так что MCP-тулсеты и наши инструменты
живут в одном раннере. Вторая: раннер **не возобновляет `pause_turn` сам** —
длинный MCP-раунд обрывает ход молча, без ошибки, поэтому паузу
обрабатываем вручную через `runner.pushMessages`. Третья: определение сервера
(`BetaRequestMCPServerURLDefinition`) принимает только `name`, `type`, `url` и
`authorization_token` — карты заголовков нет.

**Обходной путь для заголовков — строка запроса.** Раз произвольного заголовка
не передать, секрет, который сервер ждёт вне `Authorization`, кладём в URL:
у записи сервера есть `queryParams`, они вклеиваются в адрес перед отправкой.
Именно это делает `x-vercel-protection-bypass` доставляемым. **Проверено
2026-08-20: работает.** POST на `explorer.solana.com/mcp` с настоящим
секретом в query возвращает `200` без заголовка `x-vercel-mitigated`, тогда
как тот же запрос с неверным значением отдаёт `429` challenge. То есть
bypass, задокументированный для deployment protection, снимает и challenge
mode — Explorer достижим через коннектор, прокси для этого не нужен.
Explorer MCP лежит в реестре **выключенным**, с прописанным ключом и пустым
значением: секрет пользовательский, вписывается в Sources и живёт только в
памяти вкладки (как ключ API, D3). Учитываем, что он уезжает к Anthropic
внутри URL и попадёт в их логи так же, как auth-токен.

**Что это меняет в сценарии демо.** Цепочка «`get_build_error` → `read_file`
→ `program_autofixer` (MCP) → `Solana_Documentation_Search` (MCP) → патч →
`write_file`» — это уже не «модель вспоминает Anchor», а «модель сверяется с
источниками Фонда». Для презентации это главный аргумент в пользу
«заземление вместо обучения»: знания живут у Фонда и обновляются без нашего
релиза.

**Friction-лог, пункт №1.** Официальный skill и MCP учат `@solana/kit` и
**Anchor 1.1.x**, Playground собирает **anchor-lang 0.29**. Заземлённый агент
будет предлагать современный API, который среда не соберёт.

Сдерживаем двумя вещами: вшитый в бандл skill `playground-env` (реальный
whitelist крейтов, версии, «тесты только на TypeScript») и правило в промпте,
которое говорит предпочитать его любому другому источнику при расхождении о
версиях. Правило намеренно из трёх частей, а не «всегда 0.29»: пин Anchor
касается **только Anchor-программ**, нативные программы на `solana-program`
им не ограничены, а современный API можно показывать как справку, если явно
пометить, что здесь он не соберётся. Это смягчение, а не решение — прямой
аргумент к Фонду про обновление среды остаётся.

## 6. «Системные файлы»: что именно мы будем писать

Конкретный список артефактов, которые заменяют «обучение»:

1. **Системный промпт** (`model/prompt.ts`) — поведение: читать до правки,
   минимальный диф, честность про ограничения среды, формат ответа для узкой
   панели. Растёт по мере накопления friction-лога.
2. **`assistant-context.md`** — что продукт знает о себе; уже синхронизируется
   в бандл. Это ответ на «что это и что планируется» без выдумок.
3. **Описания инструментов** (`model/tools.ts`) — для модели описание
   инструмента важнее, чем кажется: именно из него она понимает, когда звать
   `get_build_error`, а когда гадать.
4. **Правила среды как skill** — по образцу официального Solana skill:
   `SKILL.md` c версиями (`anchor-lang 0.29`), списком крейтов, типовыми
   ошибками новичков (E0308, missing `#[account]`, неверные seeds PDA,
   `Signer` vs `AccountInfo`), шаблонами ответов. Загружается по запросу, не
   раздувает промпт.
5. **Набор эталонных кейсов** — §7.
6. **Friction-лог** — то, что среда не дала сделать (нужен крейт вне списка,
   Rust-тест, новый Anchor API). Уже ведётся по рабочему соглашению; это
   аргументы для следующего стратегического разговора с Фондом.

## 7. Как мы измеряем качество вместо «обучили — стало лучше»

Без этого любое утверждение «агент хорошо чинит ошибки» — вера.

- **Фикстуры**: 20–30 намеренно сломанных программ из шаблонов Playground
  (hello world, counter, PDA, token) — по одной типовой ошибке новичка каждая.
  Для каждой — ожидаемый результат: сборка проходит, диф затрагивает только
  нужные строки.
- **Прогон**: скрипт поднимает провайдера с фикстурой, отправляет «почему не
  собирается?», автоматически одобряет `write_file`, запускает сборку на
  `api.solpg.io`, фиксирует: починено/нет, число ходов, токены, стоимость.
- **Когда гоняем**: при каждом изменении промпта, skill'а, модели, `effort`.
  Так мы отвечаем на вопрос «Sonnet достаточно или нужен Opus?» цифрой, а не
  мнением.
- **Что показываем Фонду**: таблица «доля починенных / средняя цена хода /
  среднее время» по моделям. Это и есть аргумент при выборе, кто платит за
  инференс.

## 8. Ограничения и риски, о которых надо сказать честно

- **Среда ставит потолок.** Модель знает Anchor 0.30/0.31 и Pinocchio, а
  Playground собирает 0.29 с фиксированным списком крейтов. Агент будет
  тянуться к современным API — это сдерживаем промптом и skill'ом, но это
  костыль; настоящее решение — обновление среды (вопрос к Фонду).
- **Ключ в браузере** (D3) — приемлемо для демо, закрывается ступенью 1.
- **Rate limits Anthropic** на общем ключе прокси — при всплеске трафика
  анонимы упрутся в 429; нужна очередь/деградация на Sonnet/Haiku.
- **Стоимость не нулевая** — порядок $0.5–1 на бесплатного пользователя при
  10 ходах. Без ответа «кто платит» демо-режим остаётся BYOK.
- **MCP-серверы — чужая инфраструктура.** Если Solana Docs MCP упадёт,
  агент должен деградировать до знаний модели, а не падать.
- **Retention**: Opus 5 работает и при zero-data-retention; Fable 5 — нет
  (ещё одна причина не брать Fable).
